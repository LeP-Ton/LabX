# 确立 LabX 产品愿景与核心内容架构

## 背景与目标

- 用户明确 LabX 是公司的综合门户网站，用于通过 GitHub 工程化保存和管理公司的产出内容。
- 将产品目标、内容模块协作关系、传播转化路径和品牌视觉沉淀为项目核心认知，为后续信息架构与技术选型提供依据。

## 约束与原则

- 忠实记录已确认的愿景，不擅自确定尚未讨论的技术栈与部署方案。
- 内容模块应作为可关联、可复用的内容域，而不是彼此隔离的普通栏目。
- 数字永生属于长期核心愿景，后续实现需要同时考虑技术、隐私、伦理与用户授权。
- 黑白主题需要兼顾极简品牌表达、内容可读性和无障碍体验。

## 关键风险

- 多媒体资产体积较大，GitHub 是否直接存储全部原始文件需要结合 Git LFS（大文件存储）或外部对象存储进一步评估。
- 跨模块内容如果缺少统一标识、版本和依赖关系，后续容易产生重复资产与引用失效。
- `Life` 涉及人格、记忆及行为数据，未来需要明确数据权属、授权、隐私、安全与伦理边界。
- 外部媒体平台只能作为传播渠道，LabX 仍需形成可持续的自有内容入口和用户关系。
